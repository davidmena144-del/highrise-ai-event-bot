## نتائج الاختبارات الفعلية (مُعاد تشغيلها قبل التسليم)

- 37/37 ناجحة (5 ملفات، ~2.3 ثانية).
- 400 جلسة محاكاة عشوائية كاملة: لا انتهاك لأي ثابت (طاقة سالبة، تجاوز الحد، تنفيذ فوق السقف...).
- DP = البحث الشامل المرجعي في 300/300 إيفنت عشوائي.
- جلسة نظيفة: الفعلي = المتوقع بالضبط (درجة تحسين 100%).
- إيفنت كامل 7 أيام في المحاكي: ~0.6 ثانية، 32 ألف تذكرة، 96 انقطاع شبكة تم الاسترداد منه.
- التحقق البصري بلقطات حقيقية على شاشة موبايل 390px: اللوحة، اللعب التلقائي، التقرير النهائي.

## القدرات غير المتاحة (بصدق)

1. **تنفيذ إجراءات على حساب حقيقي**: لا يوجد API رسمي. Web API للقراءة العامة فقط، وBot API للبوتات في الغرف. لم يتم بناء أي تحكم عبر Android/accessibility لأنه قد يخالف شروط الخدمة.
2. **قراءة طاقة/مهام اللاعب آليًا**: لا endpoint رسمي. البديل المنفذ: Manual Adapter بإدخال المستخدم.
3. **بحث الفيديوهات**: يوتيوب صدّ الوصول الآلي (فحص مكافحة البوتات)؛ تم التعويض بمقالات الدعم الرسمية وأدلة المجتمع المكتوبة.

## قرارات معمارية

- Vite بدل Next.js: تطبيق محلي بلا خادم — لا حاجة لـ Next.
- لا Supabase: التخزين المحلي يكفي ويحافظ على الخصوصية.
- نافذة تخطيط متداولة 6 ساعات في الـ Auto Player (الدقة مثبتة على الأفق الكامل في الاختبارات).
- حدود maxExecutions تُفرض عند بناء الخطة (تفاصيل LIMITATIONS.md).

## أخطاء وُجدت وأُصلحت أثناء التطوير

1. الاستراتيجية الجشعة كانت تحسب التجدد أكثر من مرة في نفس الدقيقة (أصلحت + اختبار).
2. إصلاح سابق جعل الجشع يحسب مهامًا تعبر نهاية الإيفنت بينما DP تمنعها — وُحّد النموذج على سلوك المحاكي (التذاكر تُحسب عند بدء الإجراء).
3. انحراف ساعة التجدد: المحسّن كان يفترض تقدم تجدد صفري عند كل إعادة خطة → هدر نقاط في التنفيذ. أضيف `regenProgressMin` للنموذج؛ الجلسة النظيفة الآن تطابق المثالي 100%.
4. حلقة لا نهائية: إجراءات بزمن صفري + مكافآت طاقة عشوائية = طاقة ذاتية التغذية. أضيف `durationMin` لكل مهمة.
5. زر "شغّل للآخر" كان لا يعمل من حالة idle في الواجهة.
6. تعارض إصدارات vite/vitest وقاعدة @utility في Tailwind 4.
