# المعمارية التقنية

## المبادئ

1. **فصل تام بين المحسّن واللعبة**: المحسّن لا يرى إلا `EventConfig` وأرقام. كل وصول للعبة عبر واجهة `GameAdapter`.
2. **كل قاعدة ليها ثقة**: VERIFIED / USER_PROVIDED / ESTIMATED / UNKNOWN. ممنوع التعامل مع افتراض كأنه حقيقة.
3. **فشل آمن**: ما لا يمكن فعله رسميًا يرمي `UnsupportedCapabilityError` برسالة مفيدة، لا يتظاهر بالنجاح.
4. **عزل البيانات**: تخزين المحاكاة والجلسات الحقيقية في namespaces منفصلة (`hreb:sim:*` / `hreb:real:*`).

## الوحدات

### Event Intelligence (`rules.ts`)
خريطة قواعد بثقة ومصدر وتاريخ. `confirm()` يرفع الثقة لـ VERIFIED فقط بتأكيد صريح. لا يوجد مسار يجعل المحاكاة تكتب في قواعد الإيفنت الحقيقي.

### Energy Manager (`energy.ts`)
- طاقة أساسية بحد أقصى وتجدد كل N دقيقة.
- طاقة إضافية بصلاحيات؛ تُستهلك الأقرب انتهاءً أولًا (سياسة FEFO).
- بطاريات تتحول لطاقة أساسية مع احترام الحد الأقصى.

### Smart Optimizer (`optimizer.ts`)
البرمجة الديناميكية على (الدقيقة × الطاقة):

```
V(t, e) = max(
  V(t+1, min(cap, e + regenGain(t))),          // انتظار دقيقة
  reward_k · mult(t) + V(t, e - cost_k)   ∀k   // تنفيذ مهمة الآن
)
```

- الإجراءات لحظية، فتقدم التجدد دالة في الدقيقة فقط → الحالة ثنائية الأبعاد ودقيقة تمامًا (مطابقة للبحث الشامل في الاختبارات).
- التكرار داخل نفس الدقيقة محسوب بصعود e (knapsack غير محدود).
- **قيد موثق**: تقييم DP يعامل المهام كقابلة للتكرار بلا حد؛ حدود `maxExecutions` تُفرض أثناء إعادة بناء الخطة (راجع LIMITATIONS).
- البطاريات خارج الـ DP بقاعدة موثقة: استخدمها عند مضاعفة نشطة أو قرب النهاية لو التجدد لن يكفي.
- كل خطوة في الخطة تحمل تفسيرًا عربيًا وإنجليزيًا.

### Auto Player (`autoplayer.ts`)
آلة حالات: `idle → running ⇄ paused → stopped/completed/error`.
- `stopNow()` فوري من أي حالة نشطة، حتى منتصف التنفيذ.
- إعادة حساب الخطة بعد كل تغير موارد.
- استرداد أخطاء: إعادة محاولة مع backoff للأخطاء القابلة للإعادة (شبكة)، حد أقصى ثم `error`.
- استرداد جلسة: لقطة في SessionManager عند كل تغير حالة؛ `recover()` يعيد البناء من آخر لقطة.
- يتوقف تلقائيًا عند نفاد الموارد أو نهاية الإيفنت ويولّد تقريرًا نهائيًا.

### Adapters (`adapters/`)
- **SimulatorAdapter**: بيئة كاملة حتمية بالبذرة: مهام، مضاعفات، مكافآت طاقة عشوائية بصلاحية، بطاريات عشوائية، انقطاعات شبكة، انتهاء إيفنت (الطاقة المتبقية تنتهي — قاعدة رسمية).
- **ManualAdapter**: إدخال/تأكيد يدوي. لا ينفذ شيئًا في الحساب الحقيقي؛ يرجع توصيات.
- **OfficialAdapter**: placeholder يفشل بأمان مع مصفوفة القدرات.

### Session Manager (`session.ts`)
سجلات + لقطات استرداد + حارس عزل (`assertIsolation`).

### Reporting (`report.ts`)
تذاكر، طاقة مستهلكة/متجددة/مضاعة، كفاءة، درجة تحسين = الفعلي/المتوقع عند البداية.

## الواجهة

React 18 + Vite + Tailwind 4، عربية RTL بالكامل، 9 شاشات، زرار إيقاف فوري ثابت في الهيدر، شارة "محاكاة" واضحة في وضع المحاكاة.

## اختيار التقنيات

- TypeScript + React + Vite + Tailwind: مطلوبة في المواصفات ومناسبة فعلًا.
- **لا Next.js**: تطبيق محلي بلا خادم ولا SEO؛ Vite أخف وأسرع ويكفي.
- **لا Supabase**: لا حاجة لخادم؛ التخزين المحلي يكفي ويحافظ على الخصوصية.
- Kotlin/Android: خارج النطاق حاليًا؛ المعمارية (core نقي بلا اعتماد على DOM) تسمح بإعادة استخدام المنطق لاحقًا.
